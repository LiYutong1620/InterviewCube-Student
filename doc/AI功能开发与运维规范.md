# 面立方・多 Agent 模拟面试系统  
# AI 功能开发与运维规范（V1.0）

## 1. 总则

### 1.1 目的

规范本系统 AI 功能（简历解析、AI 出题、AI 实时追问、智能评估报告）的开发、调用、安全与审计，保障 AI 能力**合规、可控、可靠**，输出结果真实可用、可人工复核。

### 1.2 适用范围

适用于系统中所有调用大模型 API 及多 Agent 编排的模块，包括但不限于：

- 简历解析与结构化抽取  
- 基于岗位画像 / 简历的面试题目生成  
- 面试过程中的实时追问  
- 作答评估打分与复盘报告文本生成  

不适用于：确定性业务逻辑（CRUD、数据隔离、PDF 排版导出、手工填分演示入口等）。

### 1.3 引用依据

- 《生成式人工智能服务管理暂行办法》  
- TC260《生成式人工智能服务安全基本要求》及相关实践指南  
- 《中华人民共和国个人信息保护法》  
- 《中华人民共和国数据安全法》  
- 《中华人民共和国网络安全法》  
- 本仓库：`doc/学生端对外契约.md`、数据隔离工具 `StudentDataScopeUtils`

### 1.4 基本原则

| 原则 | 要求 |
| :--- | :--- |
| **最小必要** | 仅采集 / 传入完成当次 AI 任务所需数据，不额外收集 |
| **人机协同** | AI 结果仅作辅助参考；最终判断由用户或人工完成，**不自动决策** |
| **安全可控** | 防范提示词注入、越权访问、违规内容输出；可一键停用 AI |
| **可追溯** | 每次调用留审计日志，可定位、可复盘 |
| **知情授权** | 涉及简历、作答等个人信息的 AI 处理，须经用户明确授权 |

### 1.5 与本仓库现状对齐（重要）

| 能力 | 仓库现状（截至文档更新日期） | 本规范约束时点 |
| :--- | :--- | :--- |
| 简历上传 / 档案 / 个人中心 / 面试流程 CRUD | ✅ 已落地 | 非 AI，但仍须遵守数据隔离与授权 |
| 复盘报告 PDF 导出 | ✅ 已落地（OpenPDF 确定性生成） | **不属于 AI**；不得把 PDF 失败当成模型故障 |
| 手工填分 `POST /interview/report/fill` | ✅ 演示入口 | 阶段三 AI 评分上线后应替换或下线，见契约文档 |
| 简历 AI 解析、`parse_*` 字段 | 字段已预留，逻辑未接 | 接入时遵守本规范 §3～§7 |
| AI 出题 / 追问 / 智能报告 | ⏸ 阶段三押后 | 接入前完成 §8 测试与评审 |

## 2. AI 功能范围界定

### 2.1 允许的能力（辅助生成类）

本系统 AI **仅**承担以下能力，**不做**任何自动决策、自动审批、自动改库：

1. **简历解析**：从已上传简历中抽取结构化信息，回写解析状态字段（如 `parse_status`），供用户确认。  
2. **题目生成**：基于岗位画像（行业 / 岗位 / 难度等）及可选简历要点，生成面试题并落库为 `interview_question`（来源标记为 AI 生成）。  
3. **实时追问**：根据当前题与作答上下文生成追问文本，经后端校验后展示。  
4. **评估与报告**：对作答进行多维评分与总结 / 薄弱点 / 建议文本生成，写入 `interview_report`（含五维分、总结等）；用户可再导出 PDF（PDF 本身非 AI）。

### 2.2 多 Agent 编排约定

「多 Agent」指逻辑上的职责拆分，**不是**前端各自直连大模型。统一由**后端编排服务**调度：

| Agent（逻辑角色） | 职责 | 禁止事项 |
| :--- | :--- | :--- |
| 解析 Agent | 简历文本 → 结构化 JSON | 不得直接改用户档案表；结果须用户确认后落库 |
| 出题 Agent | 岗位 / 难度 → 题目列表 | 不得绕过场次状态机直接开场 |
| 追问 Agent | 上下文 → 追问句 | 不得读取其他用户会话 |
| 评估 Agent | 作答 → 分数 + 评语 | 不得在未授权时调用；分数展示须带「AI 生成」标识 |

编排原则：

- 前端只调本系统业务 API，**禁止**在浏览器持有模型密钥或拼装 system prompt。  
- Agent 之间传递的上下文须最小化，并继承当前用户的数据归属（`user_id`）。  
- 任一 Agent 失败应可降级到「题库抽题 / 手工填分 / 友好提示」，不拖垮主流程。

### 2.3 明确禁止

- AI 直接执行业务写操作（改简历定稿、改场次状态、删用户等）  
- AI 结果未经标识伪装为人工专家结论  
- 用 AI 输出替代用户协议、隐私政策或法律意见  
- 跨用户共享会话上下文（串话）

## 3. 输入处理规范

### 3.1 权限与数据归属

- AI 调用前必须校验登录态与权限标识（学生端业务权限形如 `interview:xxx:*`）。  
- **强制**经 `StudentDataScopeUtils`（或等价归属校验）确认：仅能处理当前用户本人的简历、场次、作答、报告。  
- 拥有 `interview:data:all` 的管理角色若调用 AI，须单独审计，且默认仍应对目标用户身份做显式授权记录。

### 3.2 长度与结构

- 对提交给模型的文本（简历正文、作答、上下文）设置最大 token / 字符上限；超长截断并提示用户。  
- 约定结构化输入字段白名单，拒绝未声明字段进入 Prompt。

### 3.3 敏感信息保护

- 识别并脱敏：身份证号、银行卡、精确住址、明文密码等；手机号等按策略掩码后再送模。  
- 原始业务数据按需留存在业务库（如 `student_resume`），**不得**为「方便调试」把完整简历明文写入日志。

### 3.4 提示词注入防护

- 检测用户输入中的劫持模式（如「忽略之前的指令」「忽略系统提示」等）；命中则拦截本次调用并记告警日志。  
- 用户内容一律作为**数据**放入隔离区块（如明确分隔符 / JSON 字段），不得与 system prompt 拼接成可被改写的指令流。

### 3.5 内容安全预审

- 用户输入先经内容安全审核（自建或云厂商）；命中违规类别则**阻断**模型调用，并向用户返回合规提示。

## 4. 模型调用与 Prompt 管理规范

### 4.1 Prompt 统一托管

- System Prompt 与少数模板 Prompt **仅允许**存放在后端配置中心 / 加密配置 / 专用表，**禁止**前端硬编码。  
- Prompt 变更必须版本化，记录：版本号、修改人、时间、原因、关联用例结果。  
- 生产环境禁止使用「未评审」的临时 Prompt。

### 4.2 密钥与凭证

- 模型 API Key、Secret 使用环境变量或密钥托管服务注入运行时。  
- **禁止**写入仓库、前端包、截图、演示视频。  
- 密钥轮换周期与泄露应急流程由运维负责人制定并演练。

### 4.3 调用控制

| 控制项 | 要求 |
| :--- | :--- |
| 超时 | 接口级超时；超时返回可重试友好提示 |
| 限流 | 按用户 / 接口 / 租户配额，防刷调与费用溢出 |
| 重试 | 幂等调用可有限次重试；非幂等须防重复落库 |
| 参数 | 生产环境钉扎模型名与版本；温度等采样参数有默认值与上限 |

### 4.4 降级策略

1. 主模型不可用 → 切换备用模型（需同级安全能力）。  
2. 全部模型不可用 → 返回友好提示，引导使用题库抽题 / 手工填分等非 AI 路径。  
3. **不得**因 AI 故障导致用户无法结束面试或查看已有报告。

### 4.5 数据训练开关

调用第三方模型时，**关闭**「使用用户数据用于模型训练 / 优化」类选项；合同与控制台配置双确认。

## 5. AI 输出规范

### 5.1 内容标识

凡 AI 生成内容（解析结果、面试题、追问、评语、报告正文）必须在界面显著位置标注，例如：

> 本内容由 AI 生成，仅供参考，请人工复核。

不得伪装为人工面试官或专家终审结论。

### 5.2 输出二次审核

模型返回结果在写入业务表或展示前，须做内容安全二次校验；违规则丢弃结果、记审计，并向用户提示「生成失败，请重试或联系管理员」。

### 5.3 格式与校验

- 约定输出为 JSON 或受限 Markdown；后端做 schema 校验。  
- 评分类输出须校验数值范围（如各维 0～100）、必填字段完整性。  
- 格式异常时捕获并返回友好提示，**禁止**把原始堆栈或模型原始错误暴露给前端。

### 5.4 幻觉与评分可信度（评估 Agent 专项）

- 评估须基于用户实际作答文本，禁止捏造用户未说过的经历。  
- 对明显空答 / 过短作答应降权或返回「无法有效评估」而非虚高分数。  
- 阶段三上线初期，建议保留「人工改分 / 手工填分」兜底入口（权限受控）。

### 5.5 行为边界

AI **仅**生成文本 / 结构化结果；由本系统 Service 层在校验与授权通过后落库。  
**禁止**让模型「工具调用」直接改库、调任意内部管理接口。

---

## 6. 数据与隐私规范

### 6.1 用户授权

- 简历 AI 解析、AI 测评等入口须经用户明确授权（勾选 / 弹窗确认，可记入操作日志）。  
- 未授权时不调用模型、不展示对应 AI 能力入口。  
- 个人中心已提供用户协议与隐私政策配置位（`student.agreement.*`），AI 相关条款应与之保持一致并同步更新。

### 6.2 会话隔离

- 不同用户的 AI 会话上下文严格隔离，禁止串话。  
- 会话过期或面试结束后清理临时上下文（缓存 / Redis 等）。

### 6.3 数据最小化与存储

- 上下文仅包含完成本次任务所需字段。  
- 简历、作答、报告等敏感数据按系统现有安全基线存储；传输使用 HTTPS/TLS。  
- 对接第三方时最小化字段，能摘要则不传全文。

### 6.4 学生 / 未成年人群体

本系统面向学生 / 应届生。若存在未满 14 周岁等依法需要监护人同意的情形，须在产品层增加额外同意与限制流程；默认按大学生群体设计，但仍应避免过度采集敏感个人信息。

## 7. 日志审计规范

### 7.1 必记字段

每条 AI 调用至少记录：

| 字段 | 说明 |
| :--- | :--- |
| 调用 ID | 全局唯一 |
| 用户 ID | 操作者 |
| 功能模块 | 解析 / 出题 / 追问 / 评估 |
| 调用时间 | 起止或耗时 |
| 模型标识 | 厂商 + 模型名 + 版本 |
| 脱敏输入摘要 | 禁止完整身份证 / 简历全文 |
| 输出摘要 | 截断后的摘要或哈希 |
| 调用结果 | 成功 / 失败 / 拦截 |
| 安全拦截标记 | 是否命中注入或内容安全 |
| Token 消耗 | prompt / completion |
| 耗时 | 毫秒 |

### 7.2 保存与访问

- 日志保存**不少于 6 个月**（如法规或合同要求更长，从其规定）。  
- 日志只读、可检索、可导出；访问权限限于安全 / 运维 / 审计角色。  
- 禁止在日志、监控大盘、告警正文中粘贴完整敏感原文。

## 8. 测试、监控与上线

### 8.1 AI 专项测试（上线前必做）

| 类型 | 要点 |
| :--- | :--- |
| 功能测试 | 各 Agent 主路径、与场次状态机联调 |
| 对抗测试 | 提示词注入、诱导违规、越权读他人数据 |
| 鲁棒性 | 超长、空输入、乱码、非目标语种 |
| 并发与限流 | 突发流量下的配额与降级 |
| 回归 | Prompt 变更后重跑用例集 |

### 8.2 监控告警

监控：失败率、超时率、安全拦截次数、Token 消耗、单用户异常调用频次。  
超过阈值触发告警，并支持追溯至调用 ID。

### 8.3 应急处置

出现大量违规输出或安全事件时：

1. 一键停用 AI 模块（功能开关）；  
2. 保留非 AI 主路径可用；  
3. 排查、修复、复测后恢复；  
4. 形成事件报告归档。

### 8.4 上线评审

新增 / 修改 AI 能力或生产 Prompt 后，须完成测试用例并经评审（开发 + 安全/负责人）方可上线。

## 9. 风险评估

本系统 AI 属于**有限风险**应用：

- AI 仅生成辅助参考内容（解析、出题、追问、评估文本与建议分）；  
- **不**自动做出影响用户重大权益的终局决策（录用、处分、学分等）；  
- 最终判断由用户或人工完成。

若未来扩展为「自动录取建议并对接外部 HR 系统」等高影响场景，须重新做影响评估并升级管控级别。

---

## 10. 第三方模型供应商要求

选用或变更模型供应商时，至少确认：

1. 具备合法合规的生成式 AI 服务资质与安全能力说明；  
2. 支持关闭训练 / 数据留存选项，或合同明确数据不得用于训练；  
3. 数据传输加密、地域与留存策略可接受；  
4. 故障 SLA、审计日志接口可满足 §7；  
5. 密钥与账号权限可按环境隔离（开发 / 测试 / 生产）。
